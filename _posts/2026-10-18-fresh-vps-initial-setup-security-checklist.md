Ви щойно орендували новенький VPS на Hetzner, DigitalOcean, OVH чи Netcup. Провайдер надіслав на пошту IP-адресу та тимчасовий пароль для `root`. Руки сверблять одразу накотити Docker, веб-сервер чи базу даних і пустити трафік.

Але зачекайте. **Сучасний публічний інтернет — це дике поле.**

Як ми наочно переконалися в нашій [статті про Cowrie SSH Honeypot](/posts/cowrie-ssh-honeypot-vps/), автоматизовані сканери та ботнети починають «стукати» у 22-й порт новоствореного сервера вже за **3–5 хвилин** після виділення публічної IP-адреси. Якщо залишити сервер у стані «за замовчуванням», його злам або перетворення на вузол ботнету — це лише питання часу.

Ось вичерпний покроковий чекліст із 7 обов'язкових дій, які перетворять ваш свіжий Linux-сервер (Ubuntu / Debian / AlmaLinux) на неприступну фортецю ще до розгортання першого проєкту.

## Крок 1. Первинне оновлення та автооновлення безпеки

Образи операційних систем у дата-центрах часто збираються місяцями раніше, тому в них гарантовано є незакриті вразливості нульового дня (0-day).

Перше, що робимо після першого входу:

```bash
sudo apt update && sudo apt upgrade -y
```

Щоб не перевіряти оновлення вручну щотижня, встановлюємо утиліту автоматичного оновлення безпекових патчів:

```bash
sudo apt install unattended-upgrades -y
sudo dpkg-reconfigure -plow unattended-upgrades
```

Цей пакет налаштовує щоденний cron, який автоматично встановлює лише критичні security-виправлення з офіційного дзеркала дистрибутива, не ламаючи сторонні додатки.

## Крок 2. Створення sudo-користувача

Робота під обліковим записом `root` — це небезпечна звичка. Будь-яка друкарська помилка в команді `rm` або запущений скрипт із зашитим бекдором одразу отримує необмежений контроль над ядром.

Створимо нового системного користувача (наприклад, `adminuser`):

```bash
adduser adminuser
```

Введіть надійний пароль та інформацію про користувача. Тепер додамо його до групи `sudo`, щоб мати змогу виконувати адміністративні завдання:

```bash
usermod -aG sudo adminuser
```

Перевіримо працездатність: перемкніться на нового користувача командою `su - adminuser` і перевірте команду `sudo whoami`. Результатом має бути слово `root`.

## Крок 3. Безпека SSH: ключі Ed25519 та заборона паролів

Більшість атак на сервери — це банальний брутфорс (словниковий перебір паролів). Якщо ви вимкнете автентифікацію за паролем і залишите лише криптографічні ключі, брутфорс втрачає будь-який сенс.

### 1. Згенеруйте сучасний ключ Ed25519 на своєму локальному комп'ютері
Забудьте про застарілий RSA 2048/4096. Сьогодні золотим стандартом є швидкий і криптографічно стійкий алгоритм **Ed25519**:

```bash
# Виконується на вашому комп'ютері (macOS / Linux / Windows PowerShell):
ssh-keygen -t ed25519 -C "adminuser@sedunlab"
```

### 2. Скопіюйте публічний ключ на VPS
```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub adminuser@IP_ВАШОГО_СЕРВЕРА
```

### 3. Налаштуйте конфігурацію SSH-демона
Замість редагування загального файлу `/etc/ssh/sshd_config`, створимо ізольований файл перевизначень:

```bash
sudo nano /etc/ssh/sshd_config.d/hardening.conf
```

Вставте такі директиви:

```text
# Забороняємо прямий вхід під root
PermitRootLogin no

# Повністю вимикаємо автентифікацію за паролями
PasswordAuthentication no
KbdInteractiveAuthentication no

# Дозволяємо лише вхід за публічними ключами
PubkeyAuthentication yes

# Безпека сесій
MaxAuthTries 3
X11Forwarding no
AllowTcpForwarding yes
```

Перевірте синтаксис конфігурації перед перезапуском, щоб не заблокувати себе:

```bash
sudo sshd -t
```

Якщо помилок немає, перезапускаємо службу SSH:

```bash
sudo systemctl restart ssh || sudo systemctl restart sshd
```

> **КРИТИЧНО ВАЖЛИВО:** Ніколи не закривайте поточне термінальне вікно! Відкрийте нове вікно термінала на своєму комп'ютері та спробуйте підключитися: `ssh adminuser@IP_ВАШОГО_СЕРВЕРА`. Переконайтеся, що вхід за ключем працює без введення пароля.

## Крок 4. Фаєрвол UFW та «пастка Docker»

Фаєрвол має пропускати лише необхідний трафік, блокуючи всі інші порти за замовчуванням.

### Базове налаштування UFW:

```bash
# Забороняємо всі вхідні з'єднання за замовчуванням
sudo ufw default deny incoming

# Дозволяємо всі вихідні з'єднання
sudo ufw default allow outgoing

# Відкриваємо SSH (порт 22 або ваш кастомний порт)
sudo ufw allow 22/tcp comment 'SSH'

# Відкриваємо порти для веб-трафіку (HTTP та HTTPS)
sudo ufw allow 80/tcp comment 'HTTP'
sudo ufw allow 443/tcp comment 'HTTPS'

# Активуємо фаєрвол
sudo ufw enable
```

Перевірити статус: `sudo ufw status verbose`.

### ⚠️ Головний підводний камінь: Docker обходить UFW!
Якщо ви розгортаєте додатки через Docker (наприклад, публікуєте порт `-p 8080:8080`), **Docker напряму модифікує ланцюжки iptables PREROUTING в обхід UFW!**

В результаті сервіс стає доступним усьому інтернету, навіть якщо в UFW порт 8080 явно закритий.

**Як це виправити:**
1. Прив'язуйте порти контейнерів виключно до локального інтерфейсу (`127.0.0.1`), якщо сервіс працює за Reverse Proxy:
   ```yaml
   ports:
     - "127.0.0.1:8080:8080"
   ```
2. Або використовуйте перевірений скрипт [ufw-docker](https://github.com/chaifeng/ufw-docker), який змушує Docker шанувати правила UFW.

## Крок 5. Захист від зловмисників: Fail2ban

Навіть якщо автентифікація за паролем вимкнена, боти продовжують бомбардувати порт SSH мільйонами запитів, забиваючи системні логи та витрачаючи ресурси CPU.

Встановимо **Fail2ban**, який аналізує системний журнал і автоматично додає IP-адреси нападників до чорного списку фаєрволу:

```bash
sudo apt install fail2ban -y
```

Створимо локальний конфіг захисту:

```bash
sudo nano /etc/fail2ban/jail.local
```

Додайте конфігурацію для захисту SSH:

```ini
[DEFAULT]
bantime  = 1d
findtime = 10m
maxretry = 3
backend  = systemd

[sshd]
enabled = true
port    = 22
mode    = aggressive
```

Запускаємо та активуємо службу:

```bash
sudo systemctl enable --now fail2ban
```

Перевірити стан в'язниці та кількість забанених ботів можна командою:
```bash
sudo fail2ban-client status sshd
```

## Крок 6. Системна гігієна: Час, NTP та Swap

Для коректної роботи аналітики логів, SSL-сертифікатів та cron-завдань життєво необхідно мати точний час.

### 1. Налаштуйте правильний часовий пояс:
```bash
sudo timedatectl set-timezone Europe/Kyiv
sudo timedatectl set-ntp on
```

### 2. Створення Swap-файлу (Файл підкачки)
Більшість недорогих VPS мають 1–2 ГБ оперативної пам’яті. Під час складання проекту чи раптового сплеску трафіку Linux Out-Of-Memory (OOM) Killer просто «приб'є» вашу базу даних або процес Nginx.

Створимо 2 ГБ підкачки на випадок пікових навантажень:

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Додаємо у fstab для автопідключення після перезавантаження:
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 3. Оптимізація використання пам'яті (`swappiness`)
За замовчуванням Linux починає скидати дані у Swap занадто рано, що уповільнює SSD. Налаштуємо систему скидати дані у Swap лише тоді, коли вільної RAM залишається менше 10%:

```bash
sudo nano /etc/sysctl.d/99-custom.conf
```

Додайте параметри:

```ini
vm.swappiness = 10
vm.vfs_cache_pressure = 50
```

Застосуйте зміни: `sudo sysctl --system`.

## Крок 7. Фінальний аудит: що слухає мережу?

Перед тим як оголосити сервер готовим до роботи, перевірте, які порти зараз відкриті:

```bash
sudo ss -tulpn
```

У виводі не повинно бути жодних неочікуваних сервісів, які слухають інтерфейс `0.0.0.0` або `:::`, окрім вашого SSH-демона (`sshd`) та фаєрволу.

## Підсумок: Захищений сервер за 5 хвилин

Виконавши ці 7 кроків, ви отримуєте:
1. **Імунітет проти брутфорсу**: паролі вимкнено, працює тільки ключ Ed25519.
2. **Захищений фаєрвол**: відкриті тільки потрібні порти, а Docker не має неконтрольованого доступу до мережі.
3. **Стабільність ресурсів**: налаштований Swap вбереже від падінь при браку RAM.
4. **Автоматичні патчі**: ядро та вразливості системи оновлюються самі.

Тепер ваш сервер на 100% готовий до розгортання [Beszel](/posts/beszel-lightweight-docker-monitoring-vps/) для моніторингу або [Coolify](/posts/coolify-selfhosted-heroku-vercel-vps/) для керування додатками!
